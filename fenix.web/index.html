Install

  1. In Fenix, press SPC h x to open the Extensions page.
  2. Search for Web: JavaScript and TypeScript, and install it. Fenix shows what it may do before it installs anything.

Or download the package and run fenix --install-extension fenix.web-1.1.0.fenixext.

About

JavaScript and TypeScript in Fenix: typescript-language-server with the CSS, HTML, Tailwind CSS, ESLint and Biome servers beside it, debugging with js-debug, Prettier or Biome as the formatter, package.json's scripts as tasks, the project doctor's checks with their fixes, outdated and vulnerable packages, snippets, and Next.js, Express, library and static site projects in the new-project wizard. Built on lang-kit (crates/lang-kit), as each language pack is. It needs Fenix 1.5 or later (extension API 1.5); on an older Fenix, Web 1.1.0 is the one you get. It depends on Config & Shell (fenix.config), installed with it, which serves JSON: package.json, tsconfig.json and the rest get SchemaStore's schemas.

Its package manager is the one the lockfile says: package-lock.json npm, pnpm-lock.yaml pnpm, yarn.lock Yarn (2 and later, berry, when there's a .yarnrc.yml or the lockfile says so), bun.lock bun; with none, corepack's packageManager, else npm.

The language servers

Fenix's own typescript-language-server stays the one for JavaScript, TypeScript and TSX; when it's found somewhere Fenix's PATH may not have (npm's global prefix, Volta's, pnpm's), it's started from there. Beside it (language-server-add), their completions, problems and code actions merged with its:
vscode-css-language-server, -html-CSS and HTML, in any project (vscode-langservers-extracted)
tailwindcss-language-serverHTML, CSS and scripts, when the project uses Tailwind (tailwindcss, @tailwindcss/vite, a tailwind.config.*)
vscode-eslint-language-serverscripts, when the project uses ESLint (web.eslint = server, the default)
biome lsp-proxyscripts, CSS and JSON, when the project uses Biome: its lints as you type

ESLint's server gives its problems when Fenix asks for them (pull diagnostics), and is given the settings it asks for (workspace/configuration): VS Code's, with flat config when the project has an eslint.config.* and the project's package manager. Its fixes, Disable no-var for this line and Fix all auto-fixable problems are on SPC c a. A project's .fenix/lsp/eslint.json is read under them. Tailwind's server gets its answers too, and starts.

Linting and formatting

With web.eslint = save, or while ESLint's server isn't installed, the project's ESLint (node node_modules/eslint/bin/eslint.js --format json <file>) runs on a script when it's saved, its problems shown with the server's: its errors as errors, its warnings as warnings, a file it ignores left alone. web.eslint = off is neither.

SPC c F -- and saving, with editor.format_on_save -- runs Biome (biome format --stdin-file-path=<file>) in a project with a biome.json or @biomejs/biome, else Prettier (prettier --stdin-filepath <file>) in one that uses it (prettier a dependency, a .prettierrc, package.json's prettier): the project's own from node_modules, run by node, else the one installed. A project that uses neither isn't formatted by it.

Debugging

The adapter is js-debug's DAP server, installed into Fenix's tools folder from its release (js-debug-dap-v1.140.0.tar.gz, the same on every machine, its SHA-256 checked) by the doctor's fix row or Web: install js-debug (started in the message line; how it ended is a notification: "Installed js-debug 1.140.0", or "Couldn't install js-debug 1.140.0" with which step failed and why, and Try again), and run as node dapDebugServer.js ${port} 127.0.0.1: Fenix starts it on a free port and connects (debug-adapter-connect, API).

SPC u u, in a project with no launch configuration of its own, offers:
Node: current filethe file you're in (TypeScript by Node 22.18 and later, which strips its types)
Node: attach (localhost:9229)to node --inspect app.js
Node: attach to a processto a Node running here, picked as it starts (${pickProcess})
Vite: dev server in Chrome (localhost:5173)Chrome on the dev server's page (pwa-chrome); start the server first
Vitest: current file, Vitest: all testsvitest run, the file or all
Jest: current file, Jest: all testsjest --runInBand

Beside these, each of package.json's scripts is a launch of its own, run by the project's manager with child processes debugged too (Node: pnpm run dev, Node: pnpm run test).

js-debug debugs each program in a session of its own, which it asks the editor to start (DAP's reverse request startDebugging, a second connection to it with the target's id); Fenix opens it, and shows it under the session it came from.

Tasks

SPC p t: each of package.json's scripts, run with the project's manager (pnpm run dev) -- dev, start, build, test, lint, format, typecheck and preview first -- and install. A pre or post script runs with the one it's named for, so it isn't listed. A task of the same name in .fenix/tools.json wins. Saving package.json makes them again.

Web: start the dev server runs the dev (or start) script in the background, beside the task pane, so the browser launch has its server; run again, it shows its output; Web: stop the dev server stops it.

The project doctor

  • Node: held to .nvmrc or .node-version (20.11.0 is that or a later 20; lts/iron is 20), else engines.node, else 18 at least; web.node names the one to use. Fix: fnm install, else volta install node@<version>.

  • Package manager: the lockfile's, at corepack's packageManager major. Fix: corepack enable <manager> when packageManager names it, else npm install -g <manager>.

  • node_modules: in step with the lockfile, by what each manager leaves there -- npm's node_modules/.package-lock.json, pnpm's node_modules/.pnpm/lock.yaml, Yarn 1's .yarn-integrity; for berry and bun, the lockfile not changed since the last install. Fix: the manager's install.

  • ESLint, Prettier or Biome: the project's, in node_modules. Fix: the install.

  • TypeScript server, CSS and HTML servers, Tailwind CSS server (in a Tailwind project), ESLint server (with web.eslint = server): each with its npm install -g.

  • Debugger: js-debug, with its install.

typescript-language-server runs TypeScript's tsserver: the project's own, else the one installed beside it. TypeScript 7, the native compiler, has none, and the server then never gets past "starting". In a project without its own TypeScript, install 5 beside the server: npm install -g typescript-language-server typescript@5.

A fix that installs something is checked again, and what it installed is used at once. The checks are made in a project with a package.json only.

Snippets

Scripts: imp, impd, impa (imports), exf, exd, af, afn, aaf (functions, async), tryc (await in try), pall (Promise.all), fetchj, forof, cl; tests: desc, it, ait, bfe, afe, vt (a Vitest file), vmock, jmock. React, in .jsx and .tsx: rfc, rfce, us, ue, um, uc, ur, hook, ctx, and in .tsx rfct (its props typed). TypeScript: int, type, union, asconst, guard, gfn, atfn.

Project templates

Fenix's wizard already has a Vite app (React, Vue, Svelte, Preact, Solid, Lit or vanilla, in TypeScript); this adds:

  • Next.js app: create-next-app's, TypeScript, the App Router and ESLint, Tailwind and src/ if you like, with the manager you pick.

  • Express API: in TypeScript, the app apart from its server so the tests call it on a port of their own, run by tsx as you edit, built by tsc.

  • TypeScript library: ES modules with their types, built into dist/, tested by Vitest, Prettier or Biome.

  • Static site: a page, its styles and a module, and a small Node server for development; nothing to install.

Files

*.jsonc, *.webmanifest, *.code-workspace, .babelrc, .eslintrc, .prettierrc, .swcrc and the like are read as JSON; *.pcss and *.postcss as CSS.

The lesson

SPC h T, Fenix's tutorial, has a lesson in its Web: JavaScript and TypeScript section, in a project of yours with a package.json: the project doctor and a fix from it, the packages page, a task, a debug session stopped at a breakpoint, and the formatter and ESLint on save. Each step is checked by what's on screen -- the page or the picker in front -- and a step whose tool isn't installed yet is skipped with s on the tutorial page; the doctor says how to install it.

Keys

After SPC m in a project with a package.json (C-k m with standard keys): p packages, d check again, i install, s start the dev server, S stop it.

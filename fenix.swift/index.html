Install

  1. In Fenix, press SPC h x to open the Extensions page.
  2. Search for Swift, and install it. Fenix shows what it may do before it installs anything.

Or download the package and run fenix --install-extension fenix.swift-1.1.0.fenixext.

About

Swift in Fenix, on Linux and macOS: highlighting, folding and indenting from tree-sitter-swift (Fenix has no Swift of its own), sourcekit-lsp as the language server, swift-format or SwiftFormat as the formatter, SwiftLint on save, SwiftPM's tasks, the project doctor's checks with their fixes, snippets, and a command-line package to start from. Built on lang-kit (crates/lang-kit), as each language pack is. It needs Fenix 1.5 or later (extension API 1.5); on an older Fenix, Swift 1.0.0 is the one you get.

It starts with Fenix. The server and the formatter are set whenever they're found; the doctor checks, and the tasks run, in a Swift project: one with a Package.swift, an Xcode project, or Swift files at its top or in Sources/. The first Swift file saved in a folder makes it one.

Swift itself

The pack doesn't install Swift: a toolchain is the platform's. The doctor's fix row (SPC m g, swift.get-swift) opens swift.org's page for this machine, which says how: swiftly (swiftly install latest) on Linux and macOS, Xcode or its command line tools on macOS, the installer on Windows.

Swift is looked for on the PATH, and where swiftly puts it (~/.local/share/swiftly/bin on Linux, ~/.swiftly/bin on macOS), where the tarballs usually go (/opt/swift/usr/bin), the command line tools' and Xcode's folders, and Homebrew's. sourcekit-lsp and swift-format are looked for beside the swift found first, so they're its toolchain's.

The server

sourcekit-lsp, which ships with every toolchain. On macOS without one found, Xcode's: xcrun sourcekit-lsp. It reads a package by itself; an Xcode project needs a compile_commands.json or a Build Server Protocol config (xcode-build-server) for its cross-file features.

Formatting

SPC c F, and saving with editor.format_on_save. swift.formatter:

  • auto (the default): SwiftFormat in a project with a .swiftformat (and no .swift-format), else swift-format.

  • swift-format: swift-format format --assume-filename <file>, its .swift-format found from the file's folder up. The one installed, or Swift 6's own swift format (Swift 5 has none).

  • SwiftFormat: Nick Lockwood's, swiftformat --stdinpath <file>, its .swiftformat found from the file's path.

  • off: Fenix's own.

On macOS the doctor's fix rows install either with Homebrew.

SwiftLint

On a saved Swift file, in a project with a .swiftlint.yml (swift.swiftlint = project), or with SwiftLint's default rules anywhere (always). It runs in the project, so its config (and those nested beside the file) is read, and a file the config excludes stays unlinted. Its rule is each problem's code.

The doctor's fix row installs SwiftLint 0.65.1's release into the pack's tools folder, checked against its SHA-256: Linux on x86_64 and arm64 (which links libcurl and libxml2, as Swift itself does), and macOS's universal binary. Starting it is said in the message line; how it ended is a notification, since a download can take a while: "Installed SwiftLint 0.65.1", or "Couldn't install SwiftLint 0.65.1" with which step failed and why, and Try again. One you installed yourself (Homebrew, Mint) is used instead.

Tasks

In a package (SPC p t): build, build release, run (run <product> for each executable product, or each executable target where it names none), test, resolve and update (swift package), lint (SwiftLint, when it lints the project), and format (the formatter, in place, on Package.swift, Sources, Tests and Plugins). The project's .env goes to each; a task of the same name in .fenix/tools.json wins.

Package.swift is read lightly, without running it: its first line's swift-tools-version and the products it names.

Changelog

1.1.0

  • For Fenix 1.5 (extension API 1.5): how installing SwiftLint ended is a notification rather than a line in the message line, since the download can take a while and you may be elsewhere -- "Installed SwiftLint 0.65.1", and the folder it's in; or "Couldn't install SwiftLint 0.65.1", saying whether its download, unpacking it or setting it up failed and why, with Try again. The newest for the tool takes the last one's place, and a failure's is taken away when you try again. Starting the install is still said in the message line. Installing swift-format or SwiftFormat is Homebrew's, run as a task, and is as it was. The README gives standard keys beside Vim's. On Fenix 1.0 to 1.4, 1.0.0 stays the one you have.

1.0.0

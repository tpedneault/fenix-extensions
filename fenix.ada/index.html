Install

  1. In Fenix, press SPC h x to open the Extensions page.
  2. Search for Ada and SPARK, and install it. Fenix shows what it may do before it installs anything.

Or download the package and run fenix --install-extension fenix.ada-1.1.0.fenixext.

About

Ada and SPARK in Fenix: their grammar (Fenix has none of its own), AdaCore's Ada Language Server for Ada and for GNAT's project files, Alire's or gprbuild's tasks, GNATprove's findings as problems, the project doctor's checks with fixes that install Alire, GNAT, gprbuild, GNATprove and the server, and snippets. Built on lang-kit (crates/lang-kit), as each language pack is.

It starts with Fenix. The server is set for Ada files whenever it's found; the doctor checks, and the tasks run, in an Ada project: an Alire crate (alire.toml), a GNAT project file (.gpr) at the top, or Ada sources. It needs Fenix 1.5 or later (extension API 1.5); on an older Fenix, Ada 1.0.0 is the one you get.

The grammar

*.ads, *.adb and *.ada are read with tree-sitter-ada 0.9.2's grammar (grammars/, MIT): highlighted, folded (packages, subprograms, tasks, protected objects, records, if, case, loops, handlers), with Enter indenting inside a unit or a statement, and the breadcrumbs and SPC c s listing them. SPARK's aspects (SPARK_Mode, Global, Pre, Post) and pragmas (Loop_Invariant, Assert) are coloured as attributes, 'Old and 'Range as properties. -- comments a line.

Project files (*.gpr) are a language of their own, gpr, read with the same grammar, which isn't theirs: their keywords, strings and comments are coloured, and they don't fold.

The server

The Ada Language Server (ada_language_server): completion, go to definition, references, rename, hover, its own problems, and formatting (SPC c F, and saving with editor.format_on_save), which it does itself with GNATformat. Project files get it too, in its GPR mode (--language-gpr).

It's told the project file to load (ada.projectFile, its own setting): the one you choose, else an Alire crate's (<name>.gpr), else the only one at the project's top. With several and none chosen, the doctor says so. In an Alire crate, with Alire found, it runs in the crate's environment (alr exec -- ada_language_server), where Alire's GNAT and the dependencies' project files are.

alr always runs with -n, so it never waits on a question. prove is there when the project uses SPARK: SPARK_Mode in a source, or GNATprove among the crate's dependencies. N is ada.proveLevel. The project's .env goes to each task.

Proof

SPC m p (ada.prove) runs the proof as the prove task does, with one message a line (--output=oneline) and past an error (-k), and shows what GNATprove found as problems, on the files they're in: a check not proved at high as an error, medium as a warning, low as information; flow analysis's and the compiler's errors and warnings as they are. A proof takes from seconds to many minutes, so it runs only when asked, not on save; its problems stay until the next run.

Alire's and the server's releases come from GitHub, each checked against the SHA-256 the pack knows, unpacked into the pack's tools folder, and used at once. Starting one is said in the message line; how it ended is a notification, since a download can take a while: "Installed Alire 2.1.1", or "Couldn't install Alire 2.1.1" with which step failed and why, and Try again. Each newer one for a tool takes the last one's place. The server's is a 110 MB download that unpacks to about 460 MB, most of it the debug symbols AdaCore ships beside it. alr install puts GNAT, gprbuild and GNATprove in Alire's install prefix, ~/.alire/bin, where the pack looks. The pack never runs alr with gnatprove, which changes the crate's manifest: to make GNATprove a dependency of the crate, run it yourself.

Programs you installed yourself are used instead: the pack looks on PATH, in ~/.alire/bin, and where GNAT's installers put GNAT (/usr/gnat/bin, /opt/gnat/bin, GNAT Community 2021's /opt/GNAT/2021/bin and C:\GNAT\2021\bin) and Homebrew does. Alire's own toolchains (~/.local/share/alire/toolchains) are named by a hash, so they're used through alr, not looked for.

Keys

After SPC m in an Ada project or file (C-k m with standard keys): d checks the project again, p proves.

Not yet

  • Running a GNAT project's mains: without Alire, there's no task that runs a built executable; alr run does in a crate.

  • Debugging: GNAT's programs debug with GDB; the pack doesn't set an adapter or launches yet.

  • Cross toolchains: the doctor checks the native GNAT; a crate that depends on gnat_arm_elf or another builds with it through alr, but isn't checked for it.

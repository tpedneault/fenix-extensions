Install

  1. In Fenix, press SPC h x to open the Extensions page.
  2. Search for Java and Kotlin, and install it. Fenix shows what it may do before it installs anything.

Or download the package and run fenix --install-extension fenix.java-1.2.0.fenixext.

About

Java and Kotlin in Fenix: Eclipse JDT LS as Java's language server, debugging with java-debug, kotlin-language-server (or JetBrains' kotlin-lsp) and Kotlin's highlighting, google-java-format and ktlint, Gradle's and Maven's tasks, the project doctor's checks with their fixes, outdated and vulnerable dependencies, snippets, and Gradle, Spring Boot and Maven projects in the new-project wizard. Built on lang-kit (crates/lang-kit), as each language pack is.

It reads the build: Gradle's settings.gradle(.kts), each project's build.gradle(.kts) and the conventions in buildSrc, or Maven's pom.xml and its modules. Each module's application plugin and main class, Kotlin, Spring Boot, and the Java release the build asks for (a toolchain, jvmToolchain, sourceCompatibility, maven.compiler.release) come from there. Gradle's files are code, so they're read for the forms people write, not run. It needs Fenix 1.5 or later (extension API 1.5); on an older Fenix, Java 1.1.0 is the one you get.

Java's language server

The pack is Java's language server to Fenix, and runs Eclipse JDT LS 1.63.0 behind it, passing each message on. That way it gives JDT LS java-debug's bundle and the project's JDK (java.configuration.runtimes, Gradle's Java home) in initialize, and asks it things of its own: java-debug's port, the main classes, a main class's classpath.

The doctor's fix rows install JDT LS (the milestone's tarball, its SHA-256 checked) and, since it runs on Java 25 or later, Temurin's JRE 25 when the machine's Java is older. That runtime is called fenix-java in the tools folder, so that java is still the project's. JDT LS's workspace is the pack's own folder's (${data}/jdtls-workspace/<project>), apart from what it installs. Starting an install is said in the message line; how it ended is a notification, since a download can take a while: "Installed Eclipse JDT LS 1.63.0", or "Couldn't install ..." with which step failed and why, and Try again. Each newer one for a tool takes the last one's place. Eclipse's .project, .classpath and .settings stay in that workspace; JDT LS's own build goes to bin/.

Kotlin

Fenix doesn't highlight Kotlin itself: the pack brings tree-sitter-kotlin's grammar compiled to WebAssembly (grammars/, its source and licence there), with highlighting, folds and indents (queries/kotlin). *.kt and *.kts are Kotlin, Gradle's build scripts too.

The server is JetBrains' kotlin-lsp --stdio when it's installed (Homebrew's, or its script on PATH), else kotlin-language-server 1.3.13, which the doctor installs. kotlin-lsp isn't installed by the pack: it's partly closed-source, its macOS archive is a .sit, and it's still alpha. kotlin-language-server is no longer developed; its Kotlin 2.1 can't run on Java 25, so it runs on the project's java (java.jdk says which), and the doctor says so when that's 25.

Formatting and linting

SPC c F -- and saving, with editor.format_on_save -- runs google-java-format on a Java buffer (google-java-format -: its native build where there is one, else its jar) and ktlint on a Kotlin one (ktlint --format --stdin --stdin-path=${file}). Without google-java-format, JDT LS formats. ktlint ends badly while there's a problem it can't fix, but what it could fix is taken all the same; saving a Kotlin file runs ktlint as a linter (java.ktlint_on_save), which says what's left. JDT LS and the Kotlin server give their own problems.

Debugging

java-debug is a JDT LS plugin: once JDT LS has read the project, the pack asks it to start java-debug (vscode.java.startDebugSession), and Fenix connects to the port it says. java-debug's launch needs the classpath, which a launch file can't carry, so every session attaches, on 5005:
Java: the main classJava: debug a main class (SPC m m) runs the main class you're in (or picks one of JDT LS's) held for the debugger; an application's own main class runs by Gradle's run --debug-jvm, which builds the Kotlin JDT LS doesn't
Java: the testsJava: debug the tests (SPC m t): the test class you're in, else its module's, by ./gradlew test --debug-jvm or mvn test -Dmaven.surefire.debug
Java: attach (remote, port 5005)a JVM started with -agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=*:5005

Each runs as a task; SPC u u (C-k u u with standard keys) and the launch file then attach. The adapter is Java's: breakpoints in Kotlin files weren't tried, and java-debug finds a breakpoint's class through JDT LS, which doesn't read Kotlin.

Tasks

SPC p t: Gradle's build, test, clean and check, each project's run (bootRun for Spring Boot) and test, and -- once gradle tasks --all has said what there is -- the build's own (a group of its own, bootJar, installDist, javadoc). Maven's: clean, compile, test, package, verify, install, clean install, each module's test and package, and spring-boot:run or exec:java for one that runs. They run the wrapper when it's there and can run (gradlew with its jar, mvnw; gradlew.bat and mvnw.cmd on Windows), else Gradle or Maven. A task of the same name in .fenix/tools.json wins. Saving a build file reads the build again.

The project doctor

  • JDK: javac -version, held to the release the build asks for. Fix: Temurin's download page for it.

  • Gradle wrapper / Maven wrapper: there, and its Gradle able to run on the JDK (Gradle 8.14 runs on Java 24 at most, 9.1 on 25). Fix: gradle wrapper --gradle-version 9.8.2; Maven's script-only wrapper.

  • Server runtime: Java 25 for JDT LS. Fix: Temurin's JRE 25.

  • Language server: JDT LS, installed, starting or ready. Fix: install it.

  • Debugger: java-debug 0.53.1. Fix: install it.

  • google-java-format, and for Kotlin Kotlin server and ktlint. Fix: install each.

Snippets

Java: cls, rec, iface, enum, sealed, main, mainc, ctor, sout, fori, foreach, try, tryr, sw (a switch expression), stream, groupby, opt, log; JUnit 5's test, ptest, tclass, before, athrows. Kotlin: data, cls, sealed, enum, obj, comp, main, fun, ext, when, lazy, test; coroutines' rb, launch, async, sfun, scope, wctx, flow, ctest.

Project templates

  • Gradle application, Gradle library: Java or Kotlin, Kotlin DSL, a toolchain (21, 25 or 17; the foojay resolver downloads it), JUnit 5.

  • Spring Boot: Spring Boot 4.1 on Gradle, a JSON endpoint and its MockMvc test, Actuator if you like.

  • Maven: a Java app, its release, JUnit 5, exec:java, the versions plugin.

Each makes its wrapper with the Gradle or Maven installed (needs), as the wizard can't write the wrapper's jar.

Keys

After SPC m in a Gradle or Maven project (C-k m with standard keys): p dependencies, d check again, m debug a main class, t debug the tests, r read the build again.

What the pack says when JDT LS isn't installed (the project doctor's keys) or a program is waiting for the debugger (the keys that start a debug session) names them as the scheme in use has them, or what you or Fenix bound.

Install

  1. In Fenix, press SPC h x to open the Extensions page.
  2. Search for PHP, and install it. Fenix shows what it may do before it installs anything.

Or download the package and run fenix --install-extension fenix.php-1.0.0.fenixext.

About

PHP in Fenix: highlighting, folding and indenting from tree-sitter-php's grammar, Intelephense or Phpactor as the language server, the project's own Pint or PHP CS Fixer as the formatter, PHPStan on save, Composer's scripts and the project's tools as tasks, the project doctor's checks with their fixes, snippets, and a Composer package in the new-project wizard. Built on lang-kit (crates/lang-kit), as each language pack is. It needs Fenix 1.5 or later (extension API 1.5); on an older Fenix, PHP 1.0.0 is the one you get.

The project's own tools -- PHPUnit, Pest, PHPStan, Pint, PHP CS Fixer -- are found in its vendor/bin first, then where composer global require puts them (~/.config/composer/vendor/bin, ~/.composer/vendor/bin, %APPDATA%\Composer\vendor\bin). PHP itself is looked for on PATH, Laravel Herd's folders, Homebrew's and C:\php.

The language

Fenix has no PHP of its own: the pack's language file brings tree-sitter-php 0.24.2's grammar, compiled to WebAssembly (where it came from, and its SHA-256, in grammars/README.md), and its queries. .php, .phtml, .php4 to .php8, .phps and Laravel's artisan are PHP. The HTML around the PHP is read but not coloured: Fenix doesn't highlight one language inside another. gcc comments with //.

Formatting

SPC c F -- and saving, with editor.format_on_save -- runs the project's own formatter with its config: Pint where the project uses it (pint.json, laravel/pint in composer.json, or vendor/bin/pint), else PHP CS Fixer (.php-cs-fixer.php or .php-cs-fixer.dist.php, friendsofphp/php-cs-fixer). Neither formats text on its stdin, so PHP runs it on a copy of the buffer and gives the copy back; a file it can't parse is left as it was. A project with neither is formatted by the language server. php.formatter set to server always asks the server.

PHPStan

When a PHP file is saved in a project that uses PHPStan (phpstan.neon, phpstan.neon.dist, phpstan/phpstan or Larastan in composer.json), the project's PHPStan analyses it with the project's config (analyse --error-format=json) and its problems are shown with the server's, each with its identifier (argument.type) and its tip. php.phpstan turns it off.

Tasks

SPC p t: each of composer.json's scripts (composer run-script), the everyday ones first (test, lint, analyse, format); Composer runs its pre- and post- event scripts itself. Where no script does it: test (the project's Pest, else PHPUnit), phpstan (analyse) and format (Pint, or php-cs-fixer fix). Laravel's serve (php artisan serve). And Composer's install, update, outdated (--direct) and audit. The project's .env goes to each; a task of the same name in .fenix/tools.json wins. Saving composer.json, composer.lock or a tool's config, or a task that changes them, makes them again.

A fix that installs something is checked again, and what it installed is used at once. Phpactor's, the one that downloads, says it's started in the message line; how it ended is a notification, since a download can take a while: "Installed Phpactor 2026.10.07.0", or "Couldn't install Phpactor 2026.10.07.0" with which step failed and why, and Try again. The others run as tasks.

Snippets

Files: php (<?php, strict types, a namespace). Types: class, rclass (a readonly class), ctor (constructor promotion), enum (a backed enum), iface, trait. Functions: fn, met, arrow. Control: foreach, forek (with the key), match, try. Tests: test (a PHPUnit test case), tm (a test method), dp (with a data provider), it (Pest). And dd.

Project templates

  • PHP · Composer package: PSR-4 autoloading from src/ under the namespace you give, strict types, PHPUnit with a data provider, and composer test; made with composer install.

Keys

After SPC m in a PHP project or file (C-k m with standard keys): d checks the project again, i runs composer install.

Not yet

  • Debugging: Xdebug needs its DAP adapter, which is Node and VS Code's; it comes in a later version.

  • Blade templates (*.blade.php): read as PHP, without Blade's own directives.

Install

  1. In Fenix, press SPC h x to open the Extensions page.
  2. Search for Regex, and install it. Fenix shows what it may do before it installs anything.

Or download the package and run fenix --install-extension fenix.regex-1.0.0.fenixext.

What it may do

Fenix holds it to these, and shows them before installing it. Everything else is closed to it.

Sees where you are in the editor – the file, the cursor, the selection – when its commands run

About

A playground for regular expressions (SPC s x): a pattern, a text to try it on and a replacement, matched as you type.

  • Matches, on a background in the text: the whole match the selection's, each capture group its own colour from the theme's palette, the same colours on the groups in the pattern; an empty match underlines the character after it. Under them every match, its line and column, and its groups -- numbered and named -- with where each matched.

  • In the file you're in, too: it opens beside it, and while it's open the matches are marked there the same way, as you type the pattern or the file. Go to another file and they move to it; close the playground and they go.

  • The replacement's result, live: $1, ${name}, $$ for a $.

  • Flags as toggles: i case-insensitive, m multi-line, s dot matches newline, x extended, u Unicode.

  • The pattern explained, a piece a row, nested as it nests: \d{4} "a digit, exactly 4 times".

  • Errors marked under the pattern where they are, with what's wrong.

  • Flavours: Rust's regex, or fancy-regex (f) for lookaround, atomic groups and backreferences. A note says where JavaScript, Python and PCRE read the pattern otherwise: lookbehind, named groups, \d and Unicode, $, inline flags.

  • Copies for Rust, Python, JavaScript, Go, Java and C# (y): the string literal each wants, its flags with it, named groups written its way. Or the result, or the matches, a line each.

  • Saved patterns (w): by name, for the project you're in, or for every project (W). o opens one, D forgets one. They're kept in the extension's own folder.

  • The cheatsheet (Tab, or SPC s X): classes, anchors, quantifiers greedy and lazy, groups, lookaround, backreferences, flags, and recipes -- email, URL, IPv4, dates, times, semantic versions, UUIDs, log lines. Enter loads an example into the playground; / filters.

It opens on the regex under the cursor -- a Rust Regex::new(r"..."), a Python re.compile(r"..."), a JavaScript /.../i, Go, Java or C#; the nearest when the cursor's on none -- or with the selection as the text. A line with no regex on it is the text. Open already, the playground is brought forward with the regex or the selection you're on; a line with no regex leaves its text as it was.

Tab ?Not typing: the cheatsheet, and back
PageUp PageDownA screen of the page; typing the text, of its lines
Ctrl+Z, Ctrl+Shift+Z (Ctrl+Y)Undo, redo in the fields: characters typed on in one field are one step

With the mouse: a click in a field types there, where you clicked; on a match picks it, and a double click copies it; on a flag, the flavour or a tab, that. In the cheatsheet a click picks an entry and a double click tries it. The wheel scrolls the page.

What it may do

  • Where you are: read the line or selection you open it on, where the cursor is on it, the file's language and its project.

  • The file you're in: be told which it is and when it's typed in (events = ["focus", "changed"]), read its text, and mark its matches in it while the playground's open.

Install

  1. In Fenix, press SPC h x to open the Extensions page.
  2. Search for Jupyter notebooks, and install it. Fenix shows what it may do before it installs anything.

Or download the package and run fenix --install-extension fenix.jupyter-1.1.0.fenixext.

About

Jupyter notebooks (.ipynb) in Fenix. A notebook opens in it however you open it -- the explorer, the file picker, :e, a recent file -- as its cells one under another: code highlighted on a panel with its [n] beside it, markdown as it reads, and each cell's outputs below it, with Out[n], tracebacks in red and matplotlib's plots (and any other PNG, JPEG, GIF or WebP) drawn as pictures.

hw1.ipynb  Python 3 (ipykernel) · idle · .venv · 6 cells · not saved

▌         Homework 1
▌         Read the data, greet the grader, plot it.

     [1]: with open('data.txt') as f:
              values = [int(x) for x in f.read().split()]
          print('read', len(values), 'values')
          sum(values)
          read 8 values
  Out[1]: 31

     [2]: name = input('Your name: ')
          print(f'Hello, {name}!')
          Hello, Ada!

A click focuses a cell, a double click edits it.

The commands (SPC :) run every cell, interrupt, restart, clear every output, and install ipykernel, for the notebook you were last in.

Changes go through the notebook's buffer

A cell edited, made, moved, deleted or run is an edit of the notebook's buffer, as if typed: the file changes when you save (w), and Fenix's undo has each change. Only what changed is replaced, and the notebook is written as Jupyter writes it -- keys in order, a space a level, sources and text as lines -- so a notebook from Jupyter, VS Code or Colab saved here differs only where you changed it, and a diff of it is small. Edited in its text (t), the page reads it again as you go.

Running cells

The first cell you run starts the notebook's kernel, in the notebook's folder (so open('data.csv') finds the file beside it), on its Python:

  1. the one jupyter.python names (SPC ,, Ctrl+K , with standard keys), when you set it;

  2. else the project's .venv (or venv);

  3. else, in a uv project (a pyproject.toml), uv run --with ipykernel;

  4. else python3 (python on Windows) on PATH.

When that Python has ipykernel, cells run on a real Jupyter kernel (the notebook's own, by its kernelspec, or python3): IPython's magics, display(), rich reprs, everything Jupyter does. When it doesn't, they run on that Python itself, so a notebook runs with nothing installed:

  • the last line's value is shown as Out[n], print()'s output below the cell;

  • input() asks you for a line in Fenix's modeline;

  • matplotlib's figures are drawn as pictures, on plt.show() and at the end of the cell;

  • !command, %pip install, %cd, %time and %matplotlib work; other magics say they need IPython;

  • ii interrupts a cell (a KeyboardInterrupt), 00 starts afresh.

The footer says which it is; P (or Jupyter: install ipykernel) installs ipykernel as a task -- uv add --dev ipykernel in a uv project, uv's or the Python's own pip otherwise -- and says when it's done, after which 00 restarts the kernel with it.

What a cell runs is yours: the kernel runs with your permissions, as Jupyter's does. Fenix's sandbox holds the extension to running Python (and uv) only, but not what Python then does.

The lesson

SPC h T, Fenix's tutorial, has a lesson in its Jupyter notebooks section: a notebook opened on its page, a cell edited beside it, and cells run. Its practice text is a small notebook: :w tour.ipynb saves it in the project, to open when you have none. Running a cell needs Python; without it, that step says what you'd see, and passes all the same.

It needs Fenix 1.5 or later (extension API 1.5). What it says names the keys of the key scheme you use, and yours where you rebound them: a kernel that ended badly says "C-k h l has why" with standard keys, "SPC h l has why" with Vim keys.

Settings

Setting
jupyter.pythonThe Python to run notebooks with; empty to find one as above. A project may set its own (.fenix/settings.toml)

Not yet

  • Widgets (ipywidgets) show their text, not the widget; HTML-only and SVG outputs say what they are, and JavaScript doesn't run.

  • A kernel for another language (R, Julia) runs when it's installed, as the notebook's kernelspec names it, but only Python is highlighted.

  • Completion and hover in a cell's editor: it's a scratch buffer, not a file the language server knows.

  • A kernel that ended badly says where to read why -- the extensions' log, C-k h l with standard keys, SPC h l with Vim keys -- and no Python found names the settings' keys the same way; a page says them again when you switch.

  • Installing ipykernel (P) says how it ended, once its task does: that 00 starts a notebook's kernel again with it, or that it failed and the task pane has why. It said only that it had started.

  • Fixed: a magic that needs IPython said i installs ipykernel, where the key is P.

Install

  1. In Fenix, press SPC h x to open the Extensions page.
  2. Search for Log viewer, and install it. Fenix shows what it may do before it installs anything.

Or download the package and run fenix --install-extension fenix.logs-1.0.0.fenixext.

What it may do

Fenix holds it to these, and shows them before installing it. Everything else is closed to it.

About

Log files in a pane: an entry a row, its line number, its level and its text, coloured by level -- errors red, warnings yellow, debug and trace dim. A stack trace, a traceback, a message over several lines is folded into the entry that starts it; Enter opens it, a JSON line pretty-printed.

*.log, a rotated *.log.1 to *.log.99, and *.out open in it however you open them -- the explorer, the file picker, :e. So does a journalctl export: journalctl -o export > boot.export, or -o json saved as .json (only one that starts as journald's does; any other JSON opens as text). Any file at all opens as a log with Logs: open this file as a log (logs.open) from the command palette.

Formats

Each line's level and time are read from how it's written:

FormatFor example
JSON lines{"time":"…","level":"warn",…}, pino's and bunyan's "level":40, Serilog's "@l", "severity", ECS's "log.level", journald's PRIORITY and __REALTIME_TIMESTAMP
logfmttime=… level=error msg="…", lvl=, ts=
Bracketed[WARN] …, [error], <debug>, Apache's [core:error]
Rustenv_logger's [2024-… INFO my_crate] …, tracing's 2024-…Z WARN my_crate: …, a panic
Javalog4j's and logback's 2024-… [main] ERROR com.acme.App - …, Spring's, a stack trace with Caused by: and ... 12 more
Pythonlogging's 2024-… - app - WARNING - …, WARNING:root:…, a traceback
syslog<34>1 2024-… (RFC 5424), <14>Mar 1 12:00:03 … and journalctl's Mar 1 12:00:03 host unit[42]: …
journalctl-o json, -o export (a row is its SYSLOG_IDENTIFIER[_PID]: MESSAGE), -o short, -o short-iso
Otherslogcat, glog, .NET's info: and fail:, logrus's ERRO[0005], nginx, Apache's access logs (5xx an error, 4xx a warning)

The levels are fatal (critical, emerg, alert, panic), error (severe, fail), warn, info (notice), debug, trace (verbose, finer) and other, for a line that says none. A time is read from the line's start (ISO 8601 with or without its zone, syslog's, ctime's, logcat's, a time of day alone), from the brackets near its start ([10/Oct/2000:13:55:36 -0700]), or from a JSON or logfmt field (text, or a number since 1970 in seconds, milliseconds, microseconds or nanoseconds).

An entry is a line with a time or a level at its start, and the lines after it that have neither. A log where few lines have one (under one in five) goes by indentation instead: only an indented line, Caused by: or ... 12 more goes with the one before. Either way an entry takes at most 2,000 lines or 1 MiB; past that the next line starts another. A panic and Exception in thread start an entry of their own. An entry whose first line says no level takes the first its other lines say (a traceback's).

logs.patterns adds formats of your own: a regular expression and the level a line matching it has, checked first.

An empty answer to /, ?, @ clears it; to +, - or =, all of them. Every filter goes with the levels shown: an entry is shown when its level is, its text has the / text, one of the + patterns and none of the - ones, its fields are so, and its time is in the range (one with no time stays). The counts on the second line are the whole log's; the third says how many are shown.

With the mouse: a click picks a row, a double click opens it, a click on the bars goes to the first entry at that time, and the wheel scrolls.

The bars count the entries over the log's time, a column each few minutes (as the pane's width and the log's span make it): red where the errors are -- every one while they're rare, else where there are more than usual -- yellow for warnings. With a filter that reads the entries (any but the levels), they count what's shown.

Big logs

A log in the project is read where it is, a block at a time: it opens at once, its first screen shown while the rest is indexed, a slice of the file each few milliseconds, the page answering and drawn again as it goes. What's kept is small -- where each 64 KiB of entries starts, and each entry's level in half a byte -- and an entry's text is read again when it's shown, so a log of gigabytes takes a few MiB (a 200 MB log, 2.4 million entries: about 3.5 MiB). A filter is worked out the same way, a slice at a time, a bit for each entry. A line longer than 64 KiB is read only that far for its level, the filters and the search.

One outside the project is read whole by Fenix, up to the 64 MiB it gives an extension; open a bigger one from its project.

Following (F, or logs.follow) looks at the file's length every second (logs.poll) and reads what was added. A log that got shorter, or whose start is another's -- truncated, or rotated and started again under its name -- is read again from its start. One from outside the project is read whole again each time.

Settings

SettingWhat it does
logs.levelsThe levels a log opens with shown: error, warn (error takes fatal with it), info, debug, trace, other. All of them when empty
logs.followFollow a log from when it opens. Off unless set
logs.patternsFormats of your own: a regular expression (^!!, | CRIT |) and its level (fatal, error, warn, info, debug, trace, other)
logs.pollHow often a followed log is looked at, in milliseconds: 200 to 60,000. 1,000 unless set

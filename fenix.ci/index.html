Install

  1. In Fenix, press SPC h x to open the Extensions page.
  2. Search for CI status, and install it. Fenix shows what it may do before it installs anything.

Or download the package and run fenix --install-extension fenix.ci-1.1.0.fenixext.

About

Your branch's CI, without leaving Fenix: GitHub Actions, GitLab pipelines or Jenkins on the modeline, a page of the branch's runs with their jobs, steps and logs, a notification when a run finishes -- and the failing jobs' logs for your coding agent, so it can fix them.

The page

The branch's latest runs (GitHub's workflow runs, GitLab's pipelines), newest first, the first opened on its jobs. A job opens on its steps (GitHub's), each with its state and how long it took.

KeyWhat it does
j, k, g, GMove
EnterA run: its jobs. A job or a step: its log, read-only, highlighted as a log
l, hOpen a run or a job, close it
rA run: re-run its failed jobs (GitLab: retry the pipeline). A job: re-run it
cCancel the run (GitLab: the job), asked first
oThe run or the job in the browser
RAsk again

A log is its end when it's big (the last 512 KiB): the colours, GitLab's section markers and GitHub's timestamps taken off.

Jenkins

Jenkins doesn't know a repository by its remote, so you name the job:

SettingWhat to put
ci.jenkins_urlYour Jenkins, https://ci.example.com
ci.jenkins_jobThe project's job: its folders and its name (space/rocket), or its address
ci.jenkins_user, ci.jenkins_tokenYour user there and one of its API tokens (your name, Security, Add new token)

The first two are per project (SPC ,, CI status). With a job named and no ci.provider chosen, the CI is Jenkins.

The page then shows the branch's builds. For a multibranch pipeline (or a folder of jobs) they're the builds of the job named after your branch; for any other job, the builds Git made of your branch (origin/<branch>), or all of them when Git has no part in the job. A build waiting in the queue shows as queued.

A build opens on its stages, each with its state and how long it took; a stage that failed opens on its steps and what each ran. That comes from the Pipeline Stage View plugin, which most Jenkins have: where it's missing, or the job isn't a pipeline, a build has one row, its console. Enter on a stage opens its part of the build's console, on a step its stage's.

KeyOn Jenkins
rBuild the job again (a job with parameters, with their defaults)
cStop the build, asked first

Unstable builds count as failed, and a stage waiting for input shows as manual (▷). Anonymous reading works where your Jenkins allows it; building and stopping want the user and the token.

When it asks

It looks at the repository every 3 seconds (Fenix's git_state). A new branch, a new HEAD or a push asks the forge at once, and after a push again every few seconds until its runs show up. Otherwise it asks every 30 seconds while something runs and every 2 minutes when nothing does; failures back off, doubling up to 15 minutes. Every listing is asked with the ETag it last came with, so an answer with nothing new is a 304 that costs GitHub's rate limit nothing; a rate limit's reset (x-ratelimit-*, ratelimit-*, retry-after) holds it back until it lifts.

Notifications

When the runs for your branch finish -- having been seen running -- a notification says so, tagged by the branch so the next replaces it: a pass quietly, a failure loudly (critical, or normal), with Open the log (the failed job's) and Open in the browser.

For coding agents

Its tool ci_failures gives an agent the branch's status, the failing jobs, the steps that failed, the lines in their logs that say what went wrong, and the end of each log (lines, 80 by default). It reads only; it's offered by default.

Where the CI is

The remote, origin (else the first), from .git/config (or git remote get-url origin in a worktree): github.com is GitHub, gitlab.com GitLab, the addresses in the settings theirs, and anything else a GitLab at the remote's host, as the Review extension takes it. A Jenkins is where the settings say (above), whatever the remote.

The tokens are Fenix's own (SPC ,, Forges): github.token, else the GitHub CLI's (gh auth token, --hostname for an Enterprise Server); gitlab.token (the read_api scope to read, api to re-run and cancel). A public repository on GitHub needs none.

Changelog

1.1.0

  • Jenkins: name your server and the project's job (ci.jenkins_url, ci.jenkins_job) and the branch's builds are on the modeline and the page as GitHub's runs and GitLab's pipelines are -- a multibranch pipeline's by the branch you're on, any other job's by the branch Git built. A build opens on its stages, a failed stage on its steps, and Enter on its part of the console; r builds the job again, c stops the build. Notifications and the agents' ci_failures tool work as they do for the others.

1.0.0

  • The first release, for Fenix 1.2 (API 1.3): the branch's GitHub Actions runs or GitLab pipelines on the modeline, a page of their jobs, steps and logs with re-runs and cancels, notifications when they finish, and the failing jobs' logs as a tool for coding agents.

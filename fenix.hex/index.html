Install

  1. In Fenix, press SPC h x to open the Extensions page.
  2. Search for Hex viewer, and install it. Fenix shows what it may do before it installs anything.

Or download the package and run fenix --install-extension fenix.hex-1.1.0.fenixext.

What it may do

Fenix holds it to these, and shows them before installing it. Everything else is closed to it.

About

Binary files as a hex dump in a pane: a row each 16 bytes, its offset, its bytes in hex, and the same bytes as text, what isn't printable ASCII as .. The bytes under the cursor are read beside the dump as numbers and as UTF-8.

firmware.bin  1,048,576 bytes (1.0 MiB) · 16 a row
offset    00 01 02 03 04 05 06 07  08 09 0a 0b 0c 0d 0e 0f  0123456789abcdef         little-endian         big-endian
00000000  7f 45 4c 46 02 01 01 00  00 00 00 00 00 00 00 00  .ELF............   u8    127
00000010  02 00 3e 00 01 00 00 00  c5 48 40 00 00 00 00 00  ..>......H@.....   i8    127
00000020  40 00 00 00 00 00 00 00  70 0b 10 00 00 00 00 00  @.......p.......   bits  0111 1111
                                                                                 u16   17791                 32581
                                                                                 ...
                                                                                 UTF-8 U+007F · 1 byte
0x0 · 0 of 1,048,576 · 0%

What's only ever bytes opens in it however you open it -- the explorer, the file picker, :e: *.bin, *.img, *.rom, *.iso, *.dmp, *.exe, *.dll, *.so, *.dylib, *.o, *.obj, *.a, *.lib, *.elf, *.class, *.pyc and *.wasm. Not *.hex: that's mostly Intel HEX, which is text, and so are *.dat and *.srec more often than not. Any file at all, those too, is shown in hex with Hex: show this file as a hex dump (hex.open) from the command palette.

A file in the project is read where it is, a block at a time as it's shown, so a file of gigabytes opens, and goes to its end, at once. One elsewhere is read whole, up to the 64 MiB Fenix gives an extension; open a bigger one from its project.

n NThe next match, the one before -- round the file's end
*Search for the selected bytes, or the cursor's
TabThe cursor to the text column and back
vStart selecting, or stop
Shift with a moveSelect as it moves
yCopy the selection (or the cursor's byte) as hex: de ad be ef
YCopy it as text; what isn't UTF-8 as �
cCopy it as code: 0xde, 0xad, 0xbe, 0xef
iShow or hide the inspector

RRead the file again
q, EscClose it

With the mouse: a click puts the cursor on a byte (in hex or in the text), a drag selects, Shift with a click selects to it, and the wheel scrolls.

The inspector reads the bytes from the cursor as u8, i8 and its bits, then u16, i16, u32, i32, u64, i64, f32 and f64 both little- and big-endian, and the UTF-8 character they start. It's beside the dump when the pane is wide enough, else below it.

Bytes are coloured by what they are: nul dimmed, printable ASCII plain, control characters and bytes past ASCII picked out.

A copy takes up to 1 MiB.

Settings

SettingWhat it does
hex.bytesPerRowBytes on each row, up to 64; 0 fits as many as the pane takes (8, 16 or 32). 16 unless set

It needs Fenix 1.5 or later (extension API 1.5), as the ui-kit it's built on is.

Changelog

1.1.0

  • For Fenix 1.5 (extension API 1.5): built against API 1.5, as the shared ui-kit it draws its dump with now is. The viewer works as it did; on Fenix 1.0 to 1.4, 1.0.1 stays the one you have.

1.0.1

  • Go to an offset is on o: : never reached the page, since Fenix keeps it for its command line.

  • x clears the selection and the match. Esc closes the page, as on every page, so it couldn't.

  • The search prompt opens empty, so what you type isn't added to the last search.

1.0.0

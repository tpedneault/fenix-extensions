Install

  1. In Fenix, press SPC h x to open the Extensions page.
  2. Search for Parquet viewer, and install it. Fenix shows what it may do before it installs anything.

Or download the package and run fenix --install-extension fenix.parquet-1.0.1.fenixext.

What it may do

Fenix holds it to these, and shows them before installing it. Everything else is closed to it.

Reads the files in your project
Sees where you are in the editor – the file, the cursor, the selection – when its commands run

About

Parquet files read in a pane. A .parquet (or .parq) opens in it however you open it -- the explorer, the file picker, :e, a recent file -- its rows as a table, columns fitted to what they hold, numbers on the right, nulls dimmed, and the focused value shown whole below.

trips.parquet  48,211,004 rows · 9 columns · 47 row groups · zstd · 1.9 GB
Rows  Schema  Tab switches

id   name      score  ok     day         at                    price
──────────────────────────────────────────────────────────────────────
  1  null        0.0  true   2026-01-01  2026-10-31T12:00:00Z   0.00
  2  craft-1     0.5  false  2026-01-02  2026-10-31T12:00:01Z   0.01
──────────────────────────────────────────────────────────────────────
row 2 of 48,211,004 · name Utf8
craft-1

Only the footer is read when it opens. Rows are read as they're shown, from the row groups that hold them -- and, when the file has a page index, only the pages that do -- so G goes to the last of a billion rows as fast as to the tenth.

The Schema view lists each column with its Arrow type, how it's stored, whether it may be null, its nulls, smallest and largest values (from the file's statistics), its size on disk and its codec; below it, the Parquet version, what wrote the file, and its metadata's keys (pandas, ARROW:schema).

KeyWhat it does
h j k l, the arrowsA cell
J K, PageDown PageUpA screen down, up
g GThe first and last row
0 $The first and last column
TabRows, Schema
EnterIn the schema, that column's rows
yCopy the value (in the schema, the column's name)
YCopy the row as CSV, with its header (in the schema, the schema)
RRead the file again
qClose it

With the mouse: a click focuses a cell, and the wheel moves the focused row.

Values are written as their types write them: dates and times in ISO form (timestamps in their zone), decimals at their scale, lists as [a, b], structs as {x: 1, y: 2}, binary as hex.

Snappy, zstd, gzip, LZ4 (and LZ4 raw) and Brotli are all read, every one in pure Rust; zstd's is ruzstd.

A file in the project is read where it is, a part at a time, whatever its size. One elsewhere is read whole, up to the 64 MiB Fenix gives an extension; open a bigger one from its project.

It needs Fenix 1.5 or later (extension API 1.5), as the ui-kit it's built on is.

Changelog

1.1.0

  • For Fenix 1.5 (extension API 1.5): built against API 1.5, as the shared ui-kit it draws its table with now is. The viewer works as it did; on Fenix 1.0 to 1.4, 1.0.1 stays the one you have.

1.0.1

  • A file in the open project is read where it is, whatever its size: 1.0.0 couldn't tell which project was open (it lacked editor = "read"), so it read every file whole and refused one over 64 MiB.

  • Why a file wasn't read is wrapped onto the lines below, not cut off after a long path.

1.0.0

Install

  1. In Fenix, press SPC h x to open the Extensions page.
  2. Search for JetBrains keys, and install it. Fenix shows what it may do before it installs anything.

Or download the package and run fenix --install-extension fenix.jetbrains-keys-1.0.0.fenixext.

What it may do

Nothing: it's data (themes, snippets, keymaps, templates) and runs no code.

About

The IntelliJ platform's default shortcuts -- the Windows and Linux keymap IntelliJ IDEA, PyCharm, CLion, Rider and the rest share -- laid over Fenix's standard keys. It's data alone: one keymap file, no code.

Fenix's standard keys are VS Code's. This only names the shortcuts where IntelliJ's differ, and only for commands Fenix has; everything else stays Fenix's. Vim keys are left as they are.

On and off

Install it from the store (Ctrl+K h x), with standard keys on (Ctrl+K t k switches between them and Vim keys). It's in use at once. Switching it off on the same page brings Fenix's own keys back.

Ctrl+K h ? lists the chords in use, each of this extension's marked from jetbrains. Ctrl+K h K lists anything wrong with a keymap. Your own keybindings.toml goes over this one, so a chord you'd rather have as it was is a [[keys]] entry there.

It needs Fenix 1.6 (the nightly counts): before that, the debugger kept F9 for its breakpoint, whatever a keymap said.

The keys

In a file's text unless it says anywhere.

Taken away

These are Fenix's standard keys, which IntelliJ uses for something Fenix has no command for. Left as they were they'd do something else, and most would edit your text, so with this on they do nothing:

ShortcutIntelliJFenix's, without this
Ctrl+WExtend selectionClose the tab (Ctrl+F4 here)
Alt+Up / Alt+DownPrevious / next methodMove lines (Alt+Shift+Up / Alt+Shift+Down here)
Ctrl+[ / Ctrl+]Code block start / endOutdent / indent
Ctrl+Shift+KPushDelete the line (Ctrl+Y here)
Ctrl+Q outside a file's textQuick documentationQuit Fenix

A few of Fenix's standard keys move to make room: next occurrence is Alt+J rather than Ctrl+D, the sidebar is Alt+1 rather than Ctrl+B in a file's text, the terminal Alt+F12 rather than Ctrl+J there, the next problem F2 rather than F8, rename Shift+F6 rather than F2, adding a cursor above or below has no key (Fenix's is Ctrl+Alt+Up / Ctrl+Alt+Down, which go through the list here), and the text size is Ctrl+= and Ctrl+Minus only outside a file's text. Everything is still in the palette and under Ctrl+K.

What it doesn't have

IntelliJ shortcuts with nothing in Fenix to run, which keep whatever Fenix's standard keys give them (often nothing):

  • Search everywhere (Shift twice): a key pressed twice isn't a chord. Ctrl+Shift+A and Ctrl+Shift+N cover much of it.

  • Clone caret above / below (Ctrl twice, then an arrow), and adding a caret with Alt+Shift+Click.

  • Basic and smart completion (Ctrl+Space, Ctrl+Shift+Space), and complete current statement (Ctrl+Shift+Enter, which stays Fenix's new line above).

  • Parameter info (Ctrl+P, which stays Fenix's go to file), quick definition (Ctrl+Shift+I), expression type (Ctrl+Shift+P, Fenix's palette).

  • Go to type declaration (Ctrl+Shift+B), super method (Ctrl+U, which stays Fenix's cursor undo), test (Ctrl+Shift+T, which stays Fenix's reopen tab), last edit location (Ctrl+Shift+Backspace), recent locations (Ctrl+Shift+E, which stays Fenix's file in the sidebar).

  • Type and method hierarchy (Ctrl+H, Ctrl+Shift+H, which stay Fenix's replace and replace in the project).

  • Highlight usages in file (Ctrl+Shift+F7).

  • Shrink selection (Ctrl+Shift+W), as there's no extend selection.

  • Block comment (Ctrl+Shift+/), toggle case (Ctrl+Shift+U: Fenix has upper and lower case apart), auto-indent lines (Ctrl+Alt+I), optimize imports (Ctrl+Alt+O), surround with (Ctrl+Alt+T), generate (Alt+Insert), override and implement methods (Ctrl+O, which stays Fenix's open a file by path, and Ctrl+I).

  • Refactor this, extract variable, method, field, constant and parameter, inline, move, copy, change signature, safe delete. A language server may offer some of them as code actions (Alt+Enter).

  • View breakpoints (Ctrl+Shift+F8), smart step into (Shift+F7), and debug the context's configuration (Ctrl+Shift+F9).

  • Bookmarks (F11, Ctrl+F11, Shift+F11, Ctrl+1 to Ctrl+9, which stay Fenix's panes).

  • Push (Ctrl+Shift+K), the VCS operations popup (Alt+`), and show diff.

  • New scratch file (Ctrl+Alt+Shift+Insert): Fenix's keymaps can't name Insert. Ctrl+N was Fenix's new scratch buffer; it's in the palette (buffer.scratch).

  • Synchronize (Ctrl+Alt+Y): Fenix's reload throws away unsaved edits, which IntelliJ's doesn't, so it isn't bound.

  • Hide all tool windows (Ctrl+Shift+F12), jump to the last tool window (F12, which stays Fenix's go to definition).

What a keymap can't take

  • Ctrl+K is Fenix's leader, so IntelliJ's commit isn't there: Alt+0 opens Git's page to commit from. Ctrl+Shift+P, Ctrl+\ and Alt+X are Fenix's too.

  • The debugger's own F-keys. Fenix's debugger has F5 (start or continue), Shift+F5 (stop), Ctrl+Shift+F5 (restart), F6 (pause), F10 (step over), F11 (step into) and Shift+F11 (step out) in every mode. A keymap can bind one, but taking one away gives it back to the debugger. So IntelliJ's copy (F5), move (F6) and bookmark (F11) keys run the debugger's instead.

  • A terminal that has the keyboard. Only Fenix's chords and your own reach past it, so Alt+F12 opens the terminal but doesn't close it from inside; Fenix's Ctrl+J and Ctrl+` still do.

  • Your desktop's keys. On Linux the desktop often takes Ctrl+Alt+L (lock the screen), Ctrl+Alt+Left and Ctrl+Alt+Right (workspaces) and Ctrl+Alt+F1 to F12 (consoles) before any program sees them, as it does with IntelliJ.

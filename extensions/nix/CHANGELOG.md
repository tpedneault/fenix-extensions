# Changelog

## 1.0.0

- The first release, for Fenix 1.5 (extension API 1.5): Nix. Its grammar (`.nix` files: highlighted, folded, indented, with their bindings as the scopes `SPC c s` and the breadcrumbs list), nixd or nil as the language server, nixfmt, alejandra or nixpkgs-fmt as the formatter, statix and deadnix on save (statix's fixes offered by `SPC c a`), tasks for a flake (`check`, `build`, `run`, `fmt`, `flake show`, and last `flake update (rewrites flake.lock)`), for a plain `default.nix` or `shell.nix` (`build`, `shell (build only)`) and for a NixOS or home-manager configuration (`nixos build`, `nixos dry-build`, `home-manager build`), pickers of a flake's outputs read from `nix flake show --json` (`SPC m b` builds one, `SPC m r` runs one, `SPC m S` enters a dev shell in a terminal, `SPC m s` the default one), the project's checks, snippets, two project templates (a flake with a dev shell, a NixOS module) and a lesson in the tutorial.
- Nothing is installed. Nix's tools come from Nix, so the pack looks on `PATH` and in the Nix profiles, and installs nothing into its tools folder. The one thing it can do about a missing language server is run it through the project's dev shell (`nix develop -c nixd`) or `nix shell nixpkgs#nixd -c nixd`: each is a fix row on the doctor, runs as a task you watch (it builds the shell or downloads the server), and is remembered in `nix.server_runner` only when it works. Nothing is started through Nix before that.
- The formatter is the one the flake's `formatter` output names (nixfmt, alejandra or nixpkgs-fmt), else the first of the three that's installed; `nix.formatter` picks one. Saving never runs `nix fmt`, which evaluates the flake on every call and takes longer than the three seconds Fenix gives a formatter; the `fmt` task runs it.
- There is no `switch` task, and no `test`, `boot`, `dry-activate` or garbage collection: nothing here changes the running system or deletes from the store. `flake update` rewrites `flake.lock`, so it's last in the list and named for it.
- Fenix 1.6 and later know a Nix project (`NIX`), in the project hub, on Home, in the modeline and in the doctor, and open it on `flake.nix` (else `default.nix`) when you've had none of its files open. It's declared only: no file makes a folder a Nix project, since a `flake.nix`, `shell.nix` or `default.nix` is far more often a dev shell or a package beside another language's project, and installing this pack never changes what another project is called. `kind = "nix"` in a project's `.fenix/settings.toml` says it by hand. The pack still loads for those files. Fenix 1.5 ignores all this and the pack works there as before: it's only data in the manifest.
